# 월드 1·2 전투 맵 비주얼 설계

## 목표

세로형 전투 화면에서 적 이동 경로와 타워 설치 칸을 즉시 구분하게 만들고, 월드 1과 월드 2가 같은 격자 위에 색만 바꾼 화면으로 보이지 않게 한다. 게임 규칙, 스테이지 경로, 웨이브와 수치는 바꾸지 않는다.

## 범위

* 월드 1은 **국경 성벽 · 밤의 평원**이다. 푸른 달빛, 짙은 잔디, 흙길, 돌무더기와 성벽 횃불을 사용한다.
* 월드 2는 **붉은 용광로 동굴**이다. 검은 암반, 달아오른 강철 길, 보랏빛 수정, 용암 균열과 증기를 사용한다.
* 전투 화면의 배경과 타일을 바꾼다. 스테이지 선택 카드에는 월드별 색 띠와 장소명을 추가해 진입 전에도 구분되게 한다.
* 새 래스터 에셋은 추가하지 않는다. Phaser 도형과 생성 텍스처만 사용해 PWA 용량을 늘리지 않는다.

## 렌더링 구조

`WorldBackground`는 월드별 하늘/동굴 실루엣과 느린 파티클만 맡는다. 새 `WorldMapPainter`는 스테이지의 `TileType[][]`을 읽어, 배경 위와 타일 아래에 정적인 지형 장식을 그리고 타일 표면을 월드별로 칠한다.

각 타일은 기존과 같이 입력 가능한 이미지 하나를 유지한다. 칸의 색, 테두리, 내부 무늬는 `WorldMapPainter`가 만든 월드별 설치 칸/경로 텍스처로 표현한다. 따라서 `GridManager`의 배치 판정, `PathManager`의 경로, `StageDef` 데이터는 변경하지 않는다.

장식은 고정 시드가 아닌 열·행의 간단한 모듈러 패턴으로 선택한다. 같은 스테이지를 다시 시작해도 배치가 같아 플레이 공간이 흔들리지 않는다. 장식은 `PATH`와 `BUILDABLE`의 가장자리 또는 `BLOCKED` 영역에만 두며, 타워·적·투사체보다 낮은 depth를 사용한다.

## 월드별 시각 규칙

| 요소 | 월드 1: 국경 성벽 | 월드 2: 붉은 용광로 동굴 |
| --- | --- | --- |
| 설치 칸 | 짙은 초록 잔디, 차가운 청록 테두리 | 검은 암반, 보랏빛 균열 테두리 |
| 적 경로 | 밝은 흙길과 돌 가장자리 | 붉게 달아오른 금속 판과 주황 림라이트 |
| 고정 장식 | 돌, 뿌리, 낮은 횃불 | 수정 기둥, 용암 틈, 녹슨 파이프 |
| 원경 | 달·능선·성벽 실루엣 | 동굴 천장·증기·용광로 빛 |
| 강조색 | 청록/금색 | 주황/자주색 |

경로는 설치 칸보다 15% 이상 밝고, 설치 가능한 칸은 1px 윤곽을 가진다. 색각 이상 환경에서도 밝기·무늬·테두리가 함께 달라 배치 가능 여부를 구분할 수 있어야 한다.

## 스테이지 선택

`StageSelect` 카드에는 ID 앞에 월드별 작은 색 띠를 두고, 월드 시작 카드(`1-1`, `2-1`)에는 각각 `국경 성벽`과 `붉은 용광로` 부제를 넣는다. 잠긴 카드의 대비와 기존 해금 판정은 유지한다.

## 성능과 오류 처리

* 전투 중 갱신되는 객체는 기존 배경의 두 파티클 레이어만 유지한다. 타일·장식·원경은 생성 후 갱신하지 않는다.
* 전체 보드(11×20)에서 정적 장식은 60개 이하로 제한한다. 새로운 타일 텍스처는 월드당 설치 칸/경로 2개, 총 4개만 생성한다.
* 알 수 없는 월드 번호는 월드 1 테마와 텍스처로 폴백한다.
* Phaser 없는 밸런스 하니스에서는 `WorldMapPainter`를 만들지 않는다. 전투 규칙 경로는 그대로여서 밸런스 시뮬레이션 결과에 영향이 없다.

## 검증

1. 테마 선택 순수 함수 단위 테스트: 월드 1·2의 서로 다른 팔레트와 알 수 없는 월드의 폴백.
2. 전체 `npm test`와 `npm run build`.
3. 420×840 뷰포트에서 `1-1`, `2-1`을 열어 경로·설치 칸·장식·스테이지 카드의 구분과 콘솔 오류를 확인한다.
4. `tests/balance/balance.test.ts`로 수치·웨이브 회귀가 없음을 확인한다.

## 제외 범위

월드 3 추가, 새 스테이지 동선, 적/타워 밸런스, UI 전면 개편, 외부 이미지 에셋은 이번 작업에 포함하지 않는다.
